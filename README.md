# Bank-Transactions-User-Spending-Behavior-Analysis-Fraud-Detection-using-PostgreSQL

> This project uses advanced SQL queries on a synthetic financial dataset to analyze user spending behavior and detect fraudulent activities. Leveraging PostgreSQL features such as **CTEs**, **window functions**, **aggregation**, and **pattern mining**, we uncover key insights about fraud patterns, transaction types, and suspicious sequences.
>
> 🔍 **Tech Stack:** PostgreSQL, pgAdmin  
> 📁 **Dataset:** Synthetic Financial Dataset for Fraud Detection ([Kaggle Link](https://www.kaggle.com/datasets/ealaxi/paysim1))
>
> ### 🔧 Key Objectives:
> - Explore user transaction behavior
> - Detect fraudulent transaction patterns
> - Analyze fraud frequency by amount and user
> - Use time-window gaps to detect fraud chains
>
> ---
> ### 🚀 Highlights:
> - 6.3M transaction records analyzed
> - 8213 unique users involved in fraud
> - 287 frauds with the same amount of ₹10,000,000 (likely generated by bots)
> - Fraud mostly observed in `TRANSFER` and `CASH_OUT` types
> - Detected 44 destinations targeted multiple times
> - Advanced use of **CTEs** + **Window Functions** to uncover short-interval frauds

---

## 📊 Outcomes / Results Summary:

| Analysis | Result |
|---------|--------|
| Total Transactions | `6,362,620` |
| Fraudulent Transactions | `8,213` |

| Fraud-Prone Types | `TRANSFER (0.77%)`, `CASH_OUT (0.18%)` |
| Most Frequent Fraud Amount | ₹10,000,000 (287 times) |
| Top Targets | 44 destinations were hit multiple times |
| Unique Users Who Committed Fraud | 8,213 (most only once) |
| Detected Fraud Chains with Small Step Gaps | None (frauds usually isolated per user) |
